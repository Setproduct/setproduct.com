# GA4: откуда берётся `click_get_a_quote_button` и что нужно завести руками

Дата: 08.11.2026

## 1. Что показал разбор

`click_get_a_quote_button` в репозитории **не существует**. Поиск по всему проекту (`.ts`, `.tsx`, `.mdx`, `.js`, `.json`) не находит ни одного вхождения в коде. Строка встречается только в двух местах, и оба — не исполняемый код:

1. CSV-выгрузки Google Analytics в `plans/` (исторические данные за июль–октябрь 2026).
2. Markdown-отчёты в `plans/`, где эти выгрузки разбирались.

Иными словами, событие физически не может быть отправлено текущей сборкой сайта. В `pages/_app.tsx` подключены ровно три скрипта: `gtag.js`, инлайновый `ga-init` и `gumroad.js`. GTM-контейнера нет, второго идентификатора GA нет, наследие Webflow (`public/js/webflow.js`) нигде не подключалось и уже удалено.

## 2. Почему событие видно в Realtime

`page_location` в GA4 — это адрес документа в момент отправки хита, а не адрес элемента, по которому кликнули. Поэтому в drill-down может стоять наш собственный URL (`/blog/tabs-ui-design`) при том, что событие пришло не из нашего кода: имя события задаёт отправитель, а не страница.

Версии, которые стоит исключить по порядку:

1. **Расширение браузера или сторонний скрипт** на нашей странице. Проверка: инкогнито без расширений, тот же путь.
2. **Старая закешированная сборка** (Webflow-версия) у конкретного посетителя. Проверка: `curl -s https://www.setproduct.com | grep -c "click_get_a_quote_button"` — ноль означает, что в текущем HTML строки нет.
3. **Чужой ресурс, встроенный в статью** (iframe, embed из CodePen и т.п.). В `tabs-ui-design.mdx` вставок нет, но проверяется через Network.

Практическая проверка в DevTools → Network, фильтр `collect` (или `google-analytics`): у каждого хита есть query-параметр `en=` с именем события. Если `en=click_get_a_quote_button` приходит из нашего документа, рядом в `dl`/`dr` видно источник. Если хит не появляется при чистой сессии в инкогнито — источник внешний.

Ещё один сигнал: в Realtime были `first_visit` 9 при `session_start` 10 и `page_view` 11. Такое соотношение бывает при нескольких «первых» визитах подряд, что типично для разных браузеров, чистки куки или автоматизированного обхода. Трафик стоит проверить в отчёте «Пользователи» по городу и по устройству.

## 3. Что закрыто в коде

Старые имена событий из Webflow (`click_get_a_quote_button`, `form_start`, `form_submit`) не восстанавливались. Вместо них заведён собственный контактный домен событий в [`lib/contact.ts`](../lib/contact.ts):

| Событие | Смысл |
|---|---|
| `contact_cta_click` | Клик по любой кнопке, открывающей модалку контакта |
| `contact_form_start` | Первый фокус в поле формы (один раз за открытие) |
| `contact_form_submit` | `/api/contact` ответил успехом |
| `contact_form_error` | `/api/contact` ответил ошибкой, с причиной |

Все четыре несут параметр `location` — точку входа. Значения: `company_panel_desktop`, `company_panel_mobile`, `template_hire`, `dashboard_cta`, `testimonials_page`, `search_page`, `faq`, `refunds_policy`, `terms_page`, `footer`. Если вызов пришёл без источника, уходит `unknown` — так пропущенная точка входа видна сразу.

`contact_cta_click` отправляется внутри `openContactModal`, а не в каждом компоненте отдельно: новая кнопка не сможет открыть модалку и при этом не отметиться.

## 4. Что нужно сделать руками в интерфейсе GA4

Код отправляет параметры, но GA4 не показывает их в отчётах, пока не объявлены свои измерения и не отмечены ключевые события.

### 4.1. Свои измерения (Admin → Data display → Custom definitions)

Создать четыре измерения со следующими настройками. Параметр и имя должны совпадать символ в символ, иначе значение не подхватится.

| Имя измерения | Параметр события | Область | Тип |
|---|---|---|---|
| Contact location | `location` | Event | Текст |
| Contact page path | `page_path` | Event | Текст |
| Contact error reason | `reason` | Event | Текст |
| Contact message length | `message_length` | Event | Число (стандартный вариант — «Метрика», GA4 допускает числовые параметры как метрику) |

Отдельно про оглавление. Параметр `location` используется и в `toc_click`, где принимает значения `sidebar` и `mobile`. Второй набор измерений на тот же параметр завести нельзя: GA4 привязывает измерение к имени параметра, а не к событию. Поэтому `Contact location` попутно собирает и значения оглавления, а в отчётах нужно фильтровать по имени события.

### 4.2. Ключевые события (Admin → Events → Key events)

Отметить как ключевые:
- `contact_form_submit` — единственный реальный лид. Всё остальное воронка до него.
- `contact_cta_click` — **не** делать ключевым, это микроконверсия, иначе конверсия раздуется в разы.

`contact_form_start` и `contact_form_error` — диагностические, ключевыми не делать.

### 4.3. Отчёт по воронке

Через Explore → Funnel exploration, шаги:

1. `contact_cta_click`
2. `contact_form_start`
3. `contact_form_submit`

Разбивка (Breakdown) — по измерению `Contact location`. Это сразу показывает, какая точка входа даёт открытия, но не даёт заполнений.

### 4.4. Проверка, что параметры доехали

Realtime → выбрать `contact_cta_click` → в блоке параметров должен появиться `location`. Если параметра нет в списке, но событие есть — значит измерение ещё не обработано (GA4 обновляет определения до 24 часов) либо имя параметра в коде разошлось с объявленным.

## 5. Ограничения, о которых стоит помнить

1. `location` — общий параметр для двух доменов событий (`contact_*` и `toc_*`). При построении отчётов всегда фильтровать по имени события, иначе значения перемешаются.
2. `message_length` — длина сообщения в символах, не в словах. Для анализа «серьёзности» запроса этого достаточно, для текстового анализа — нет (текст в GA4 не уходит и уходить не должен).
3. `contact_form_error` фиксирует и сетевые сбои, и отказы сервера. Причину смотреть в параметре `reason`; при сетевой ошибке там будет `http_<код>`.
4. Исторические данные Webflow (`click_get_a_quote_button`) с новыми событиями **не сравнить напрямую**: изменились и имена, и модель (был один клик без источника, стало четыре шага с точкой входа). Сравнение возможно только по абсолютному числу лидов.
