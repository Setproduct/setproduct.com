Статус: план, код не менялся. Версия из 6 колонок (`43fbe32`) будет откачена.

## 1. Почему не сработали первые две версии

| Версия | Что было | Почему плохо |
|---|---|---|
| A (`62f79e6`) | Start here с картинками + все 42 гайда текстом в 3 колонки | Панель почти на весь экран. Картинки битые: путь `thumbs/thumbs`. Колонка из трёх строк при высоте в 17 строк выглядит пустой |

Вывод: панель должна быть такой же высоты, как Magazine и Resources, показывать гайды по алфавиту и с миниатюрами, и при этом не грузить 42 картинки сразу.

## 2. Предложение: та же схема, что у Magazine и Resources

Слева столбец групп, справа плитки выбранной группы. Это уже знакомое пользователю поведение: наведение на группу меняет правую часть, работают menu aim, клавиатура и аналитика, которые есть в `MegaMenuPanel`.

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ Groups               │  [img] Button          [img] Checkbox       [img] Dropdown │
│ ● Inputs         10  │  [img] Button group    [img] Date picker    [img] Input field│
│   Navigation      9  │  [img] Radio button    [img] Slider         [img] Stepper  │
│   Data display    7  │  [img] Toggle switch                                     │
│   Feedback        4  │                                                          │
│   Screens         5  │                                     All inputs guides →  │
│   Visual styles   7  │                                                          │
│ ─────────────────────│                                                          │
│   All 42 guides →    │                                                          │
└───────────────────────────────────────────────────────────────────────────────┘
```

- **Алфавит.** Внутри группы гайды идут строго по алфавиту и раскладываются по строкам слева направо. Группы стоят в смысловом порядке (Inputs → Visual styles), как на хабе.
- **Миниатюры.** Плитка состоит из картинки 64×44 со скруглением `radius-12` и названия справа. На ховер плитка получает общий паттерн `hover-lift` (маленький размер), как строки на /search.
- **Высота.** Самая большая группа (Inputs, 10 гайдов) занимает 4 строки в 3 колонки, около 240px. Столбец групп 8 строк, около 300px. Вся панель примерно 340px, то есть та же высота, что у Magazine. Сейчас (вариант A) около 800px.
- **Состояние по умолчанию.** При открытии выбрана группа Inputs. Если человек сейчас на странице гайда, выбрана его группа: открыл меню со статьи про Tabs и сразу видит Navigation.
- **Ссылки групп.** Клик по группе ведёт на `/ui-guides#inputs`, как клик по категории в Magazine ведёт на отфильтрованный блог. Внизу правой части есть ссылка «All inputs guides →» на тот же якорь, внизу левой колонки «All 42 guides →» на хаб.

## 3. Картинки: правильные и лёгкие

- Ошибку с путём исправляю у источника: путь к превью берётся из `thumbImage` во frontmatter как есть, без повторной замены `covers/` → `covers/thumbs/`. Сборка падает, если файл превью не существует на диске. Так битая картинка больше не попадёт в меню молча.
- Все 42 превью весят 973 КБ, грузить их сразу нельзя. Картинки идут через `next/image` с `sizes="64px"`: в `next.config.js` ширина 64 уже есть в `imageSizes`. Оптимизатор отдаёт AVIF/WebP по 2–4 КБ на штуку, и в браузер уходят только плитки открытой группы (до 10 штук, около 30 КБ).
- Прогрев как в Resources: при наведении на группу картинки её плиток начинают грузиться до переключения (`preloadNextImage`).
- В данных навбара появляется список гайдов `{slug, label, group, thumb}`: 42 записи, около 4 КБ в props каждой страницы. Вместо этого можно положить путь к превью прямо в `data/ui-guides.ts`, и тогда в props ничего не добавится. Рекомендую второй вариант: данные статичные, проверка на существование файла всё равно идёт при сборке.

## 5. Что меняется в коде

1. `git reset --hard cd09178` (`43fbe32` не запушен, поэтому история останется чистой) или `git revert 43fbe32`, если хотите видеть откат в истории.
2. `data/ui-guides.ts`: поле `thumb` у каждого гайда, сортировка по `label` внутри группы, `UI_GUIDE_START_HERE` из навбара больше не используется (остаётся только для хаба).
3. `useMegaMenuState`: `guides` становится меню с категориями (`CategoryMenuKey`), значение по умолчанию — группа текущего гайда или `inputs`.
4. `GuidesPanel.tsx` удаляется. В `SiteHeader` вместо него `MegaMenuPanel menu="guides"` с плитками; плитка — небольшой компонент `GuideTile` (картинка + название).
5. CSS: стили `.nav-guides-*` из варианта A удаляются, добавляется блок `.nav-guide-tile` (сетка 3/2/1 колонки, размеры через `calc(N * var(--em-px))`).
6. Аналитика: `categoryLabel` для `guides` возвращает ключ группы вместо `"panel"`, так в GA4 видно, какую группу смотрят.
7. Проверка: lint, build, HTML (нет `thumbs/thumbs`, у каждой плитки есть `src`), затем 1440 / 1024 / 768 / 390, Tab и Escape.

Отдельные коммиты: откат → данные → панель → CSS и аналитика.
