## 1. Что значит «появится доступ»

Ключ сам по себе ничего не меняет. Модель не уходит в сеть по своей инициативе: вызов делает скрипт, а запускает скрипт агент, когда у него есть терминал. В Architect-режиме терминала нет, в Code-режиме есть.

| Условие | Кто делает | Без него |
|---|---|---|
| Ключ в `.env.local` | автор | скрипт падает на первом шаге |
| Скрипт `scripts/gen-image.mjs` | агент | вызывать нечего |
| Терминал у агента | режим Code | скрипт есть, запустить нельзя |

Это не «доступ к модели», а обычный HTTP-вызов из Node. Ценность в том, что ключ не попадает в клиентский код и в git.

## 2. Ключ

Лежит в `.env.local`, файл в `.gitignore` (строка 5), проверено через `git check-ignore`. Имена переменных взяты из панели сервиса, не выдуманы:

```
VENICE_API_KEY=VENICE_INFERENCE_KEY_...
VENICE_BASE_URL=https://api.venice.ai/api/v1
```

В Vercel ключ не добавляется. Сайту он не нужен ни на билде, ни в рантайме: картинки готовятся локально, в репозиторий попадает только готовый WebP. В `.env.example` имена переменных не прописаны намеренно, чтобы не намекать на обязательную настройку окружения для сборки.

**Ключ засвечен** в переписке и на скриншоте 25.11.2026. После проверки пайплайна его стоит перевыпустить: панель предупреждает «Won't be shown again», старый ключ живёт до отзыва.

## 3. Проверенные факты API (25.11.2026)

Всё ниже получено реальными запросами, не по памяти.

| Что | Значение |
|---|---|
| Авторизация | `Authorization: Bearer <key>` |
| Список текстовых моделей | `GET /models` → 148 штук, все с `model_type: text` |
| Список моделей изображений | `GET /models?type=image` → **52 штуки** |
| Генерация | `POST /image/generate` |
| Тело запроса | `model`, `prompt`, `aspect_ratio`, `hide_watermark`, `safe_mode` |
| Ошибка без модели | `400 {"error":"model is required"}` |
| Путь, которого нет | `/image/generations` → 404 |

Важная особенность: `/models` без параметра не показывает модели изображений вообще. Без `?type=image` их не найти, и это выглядит как «картинок нет».

Стили доступны через `GET /image/styles` (3D Model, Analog Film, Anime, Cinematic, Comic Book, Craft Clay, Digital Art и другие). Для плоских UI-мокапов не нужны: они тянут картинку в «красивость» и уводят от палитры.

## 4. Скрипт

`scripts/gen-image.mjs`, 160 строк. Запуск:

```
node --env-file=.env.local scripts/gen-image.mjs <name> [aspect] [model]
```

Промпт читается из `.tmp-gen/prompts/<name>.txt` — сцена плюс мастер-блок одним файлом. Готовое кладётся в `.tmp-gen/<name>-<model>-<timestamp>.webp`, плюс исходный PNG.

Четыре решения внутри, которые важны:

1. **`.tmp-gen/` вне `public/`.** Сгенерированное не должно случайно оказаться на сайте. Папка в `.gitignore`.
2. **Метка времени в имени.** По правилу проекта существующая картинка не перезаписывается никогда: иначе кеш браузера, CDN Vercel и оптимизатор Next продолжат отдавать старые байты по тому же URL.
3. **`--env-file=.env.local`.** Next читает `.env.local` сам, голый `node` — нет, а `sharp` не тянет `dotenv`.
4. **Разбор ответа на все формы.** Формат не документирован в панели, поэтому скрипт принимает `images[0]`, `data[0].b64_json`, `data[0].url`, `b64_json`, `image`, `url` и data-URL. Если сервис сменит формат, скрипт напечатает список ключей вместо тихого падения.

Синтаксис проверен через `node --check`.

## 5. Порядок внедрения

1. ~~Ключ в `.env.local`~~ — сделано.
2. ~~`.tmp-gen/` в `.gitignore`~~ — сделано.
3. ~~`scripts/gen-image.mjs`~~ — сделано, синтаксис проверен.
4. Собрать `.tmp-gen/prompts/`, по одному txt на картинку: сцена из плана плюс мастер-блок.
5. Прогнать на одном файле. Первый кандидат — №11 `glass-thickness-layers`, самая простая сцена без текста.
6. Посмотреть результат как изображение, поправить промпт, прогнать ещё дважды.
7. Только после этого идти по остальным.

**Ловушка по времени:** первый прогон был убит по таймауту 240 с (`SIGKILL`), не успев записать файл. Генерация `ideogram-v4` идёт дольше. Запускать с таймаутом от 600 с.

**Ловушка по деньгам:** ошибка валидации (`400`) бесплатна, платный только успешный вызов. Поэтому дешевле сначала убедиться, что тело запроса принимается.

## 6. Что проверить нельзя

| Утверждение | Реально |
|---|---|
| «hex `#7c4dff` вышел пиксель в пиксель» | нет. Модель уводит оттенок. Отклонение видно глазом, попадание не гарантировано |
| «текст вышел посимвольно» | нет для `--glass-highlight`, `14.02:1`, `1.33:1`. Даже Ideogram, лучший по тексту, на длинных строках ошибается |
| «стекло того же материала, что на соседней картинке» | частично. Один мастер-блок даёт похожесть, одинаковость даёт только код |
| «белый вышел ровно `#ffffff`» | нет. Проверяется пипеткой после генерации, брак перегенерируется |

Практический вывод: сцену отдаём генератору, подписи и числа накладываем кодом через `sharp` настоящим Uncut Sans из `public/fonts/`. Строку `Text` в мастер-блоке плана изображений тогда надо переписать в «текст накладывается отдельно».

## 7. Деньги

```
23 файла × 3 попытки = 69 запросов
× $0.06 (ideogram-v4) = $4.14
```

С `flux-2-pro` ($0.03) — $2.07, но лимит промпта 3000 символов заставит урезать мастер-блок. С `venice-sd35` ($0.01) — $0.69, но 1500 символов делают задачу нерешаемой в текущем виде.

Текстовый объём агента при этом небольшой, 30–40 тысяч токенов: промпты уже написаны.

Риски: суточный лимит аккаунта может не дать 69 запросов за раз, тогда партии по 10–15. Ключ может закончиться на середине, тогда пайплайн останавливается на текущем файле.

## 8. Правила проекта, которые нельзя нарушить

1. Ключ только в `.env.local`. В `.env.example` — ничего.
2. Существующая картинка не перезаписывается. Новое имя файла каждый раз, старый файл удаляется отдельно, путь правится в статье.
3. Сгенерированное сначала лежит вне `public/`. Публикация — отдельное осознанное действие.
4. `public/blog/` меняется только после приёмки.
5. Никаких `push` без команды автора.
