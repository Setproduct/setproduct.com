# Выгрузки Search Console для гайда `card-ui-design` — пошагово

Документ для автора. По нему можно пройти сверху вниз и получить 9–11 файлов.
Ничего не нужно придумывать: каждый шаг содержит точный фильтр и точное имя файла.

Итог: папка `plans/card-gsc/` с файлами `01-…` … `09-….csv`.

---

## 0. Общая подготовка (один раз, 2 минуты)

❶ Открыть Search Console, выбрать ресурс `setproduct.com`.
Важно: ресурс может быть двух типов. Если в адресах внутри отчёта стоит `www.setproduct.com`, значит используется префиксный ресурс с www. Если стоит `setproduct.com` без www, значит доменный ресурс. От этого зависит форма ссылок в фильтрах ниже (`https://www.` или `https://`). Запомнить, какой вариант виден в отчёте, и использовать его везде.

❷ Зайти в раздел `Эффективность` (Performance).

❸ Период: кнопка с датой вверху → `Своя дата` (Custom) → начало `25.08.2026`, конец `25.11.2026`.
Не брать пресет `Последние 3 месяца`: он считается от текущего дня другими границами и не совпадёт с периодом, на который ссылаются остальные документы проекта.

❹ Проверить, что в переключателе вверху стоит `Запросы` (Queries), а метрики показывают `Всего кликов, Всего показов, Средняя позиция, CTR`.
Позиция появляется справа от CTR. Снять галочку с `Средний CTR` не нужно.

❺ Как ставить фильтр, одинаково во всех шагах ниже:
`+ Создать фильтр` в строке над таблицей → выбрать измерение (`Запрос` или `Страница`) → переключить индикатор с `Содержит` на `Своя (регулярное выражение)` → вставить регулярку → `Применить`.

☛ Регулярка в Search Console чувствительна к регистру и работает по синтаксису RE2. Поэтому в шаблоны ниже добавлен флаг `(?i)` (игнорировать регистр). Без него `card` не найдёт `Card ui` и `CARD`.

❻ Как забрать файл:
справа сверху над графиком `Экспорт` → `Скачать CSV`.
Next ограничение Search Console: любой CSV отдаёт не больше 1000 строк. Если интерфейс показывает «Показано 1000 из большего числа», см. раздел 8 (что делать).

❼ Имена файлов не спрашивать у системы, а задавать сразу при сохранении:
`plans/card-gsc/01-queries-card.csv` и так далее по списку. Иначе через день не будет понятно, какой файл какой фильтр.

---

## 1. Файл `01-queries-card.csv` — все запросы с основой card

Нужен для объёма и интентов.

❶ Раздел `Эффективность`, вкладка `Запросы`.
❷ Период: `Своя дата`, `25.08.2026` — `25.11.2026`.
❸ `+ Создать фильтр` → `Запрос` → `Своя (регулярное выражение)`.
❹ Вставить:

```
(?i)card
```

❺ `Применить`.
❻ `Экспорт` → `Скачать CSV` → сохранить как `plans/card-gsc/01-queries-card.csv`.

Проверка на месте: в таблице должны присутствовать `card ui`, `ui card`, `card design`, `card component`, `card layout` или их отсутствие должно быть осознанным результатом. Если после фильтра таблица пустая, значит в ресурсе другая форма URL или регулярка отклонена. Вернуться к шагу 0.5.

---

## 2. Файл `02-pages-card.csv` — страницы по тем же запросам

Нужен для каннибализации.

❶ Не сбрасывая дату, переключить вкладку `Страницы` (Pages). Фильтр по запросу при этом сохраняется и продолжает действовать.
❷ Убедиться, что над таблицей висит плашка `Запрос: (?i)card`. Если плашки нет, поставить фильтр заново на вкладке `Страницы`.
❸ `Экспорт` → `Скачать CSV` → `plans/card-gsc/02-pages-card.csv`.

Смысл файла: это страницы, которые Google уже показывает по запросам про карточки. Каждая строка — кандидат либо в расширение существующего текста, либо в новую статью.

---

## 3. Файл `03-devices-card.csv` и `04-countries-card.csv` — устройства и страны

Нужны, чтобы понять, сколько места отдавать мобильному разделу.

❶ Тот же период, тот же фильтр `Запрос: (?i)card` (фильтры работают на весь отчёт, а не на одну вкладку).
❷ Вкладка `Устройства` → `Экспорт` → `Скачать CSV` → `plans/card-gsc/03-devices-card.csv`.
❸ Вкладка `Страны` → `Экспорт` → `Скачать CSV` → `plans/card-gsc/04-countries-card.csv`.

☛ Для мобильного раздела важна доля показов с телефона, а не кликов. Кликов по мобильным обычно меньше при той же выдаче. Если интерфейс позволяет, после экспорта свериться с вкладкой `Тип поиска` и отметить, какую долю даёт `Google Изображения`. Для гайда по карточкам это прямо релевантно: половина трафика по таким запросам приходит на картинки.

---

## 4. Файлы `05`–`11` — экспорт по каждой соседней странице

Шесть страниц, на каждую два файла: запросы и страницы. Пункт про позиции 8–20 и показы от 200 достаётся из этих же файлов, отдельная выгрузка не нужна.

Список URL (подставить форму домена из шага 0.1, ниже показана форма с www):

| № | URL | Запросы | Страницы |
|---|---|---|---|
| 1 | `https://www.setproduct.com/blog/bento-grid-layout-design-guide` | `05-bento-queries.csv` | `06-bento-pages.csv` |
| 2 | `https://www.setproduct.com/blog/chip-ui-design` | `07-chip-queries.csv` | `08-chip-pages.csv` |
| 3 | `https://www.setproduct.com/blog/data-table-ui-design` | `09-datatable-queries.csv` | `10-datatable-pages.csv` |
| 4 | `https://www.setproduct.com/blog/dashboard-ui-design` | `11-dashboard-queries.csv` | — |

Порядок действий на каждую страницу:

❶ Период `25.08.2026` — `25.11.2026`.
❷ Снять старый фильтр: `Создать фильтр` → в списке активных фильтров нажать крестик у `Запрос`.
❸ `+ Создать фильтр` → `Страница` → `Своя (регулярное выражение)`.
❹ Вставить регулярку с точной привязкой к адресу. Для bento:

```
^https://www\.setproduct\.com/blog/bento-grid-layout-design-guide/?$
```

Правило для остальных: заменить только последний сегмент пути. Точки экранировать (`\.`), `/?$` в конце оставить, чтобы адрес без хвостового слэша тоже попадал.

❺ `Применить`, вкладка `Запросы`, `Экспорт` → `Скачать CSV`.
❻ Переключить на вкладку `Страницы`, `Экспорт` → `Скачать CSV`.
❼ Повторить шаги ❷–❻ для следующего URL из таблицы.

Проверка на месте: в файле запросов после фильтра должна быть одна страница в колонке `Страницы` (если в экспорте эта колонка не выводится, ориентир другой: общее число кликов и показов должно совпадать с тем, что показывает сама карточка страницы). Если строк ноль, значит форма адреса в фильтре не совпала. Убрать `^…$` и оставить просто `bento-grid-layout-design-guide`.

### Что я заберу из этих файлов сам

→ позиции 8–20: отсортирую колонку `Средняя позиция`, интервал видно сразу;
→ показы от 200: отсортирую по `Показы` и отрежу всё ниже;
→ топ-100: возьму первые 100 строк по показам;
→ пересечение запросов: сравню списки четырёх страниц между собой и с `01-queries-card.csv`.

☛ Фильтра по средней позиции и по числу показов в интерфейсе Search Console нет: ни в фильтрах, ни в настройках отчёта. Поэтому шаги 8–20 и 200+ решаются сортировкой в самом CSV, а не отдельной выгрузкой. Если ждать отдельные файлы по этим срезам, ждать придётся впустую.

## 5. Файл `12-card-year-queries.csv` — запросы с годом (опционально, 1 минута)

Нужен для единственного решения: предлагать ли вариант title с годом.
Бриф запрещает менять title самовольно, поэтому достаточно посмотреть, есть ли спрос.

❶ Период тот же. Снять фильтр по странице, поставить новый: `Запрос` → `Своя (регулярное выражение)`.
❷ Вставить:

```
(?i)card.*20(25|26)
```

❸ `Применить`, вкладка `Запросы`, `Экспорт` → `Скачать CSV` → `plans/card-gsc/12-card-year-queries.csv`.

Ожидаемый исход: ноль или единицы строк. Тогда вариант с годом в title не предлагаю и оставляю 48 символов из брифа.

❶ Проверить, что в папке `plans/card-gsc/` лежат все файлы, кроме необязательного `12`:

```
01-queries-card.csv
02-pages-card.csv
03-devices-card.csv
04-countries-card.csv
05-bento-queries.csv
06-bento-pages.csv
07-chip-queries.csv
08-chip-pages.csv
09-datatable-queries.csv
10-datatable-pages.csv
11-dashboard-queries.csv
```

❷ Открыть каждый и убедиться, что первая строка это заголовки (`Топ запросы`, `Клики`, `Показы`, `CTR`, `Средняя позиция`), а не пустота.
❸ Если какой-то файл вышел пустым, а по ощущению данные быть должны, не досылать выдуманное, а написать, какой именно фильтр дал ноль. Разберём отдельно.

## 7. Если ресурс в Search Console только один и он доменный

Тогда адреса внутри отчёта идут без www, и регулярка из пункта 4 меняется на:

```
^https://setproduct\.com/blog/bento-grid-layout-design-guide/?$
```

Больше ничего не меняется. Признак ошибки: фильтр применён, но строки в файле нулевые при ненулевых кликах на самой странице.

---

## 8. Если строк больше 1000

Search Console отдаёт максимум 1000 строк на экспорт, и это ограничение не обходится настройками. Для `(?i)card` риск невелик, но если интерфейс пишет «Показано 1000», поступить так:

❶ Разбить регулярку на группы и выгрузить каждую отдельным файлом, добавив суффикс:
`(?i)card ui`, `(?i)card design`, `(?i)card component`, `(?i)card layout`, `(?i)card grid`, `(?i)card hover`, `(?i)product card`, `(?i)dashboard card`.
❷ Сохранить как `01a-queries-card-ui.csv`, `01b-queries-card-design.csv` и так далее.
❸ В остальных экспортах ограничение почти наверняка не сработает: там одна страница или один фильтр по странице.

☛ Отдельная тонкость: Search Console не показывает запросы с очень малым числом показов и скрывает часть запросов в целях приватности. Поэтому сумма показов в файле запросов всегда меньше, чем в общем отчёте. Это норма, а не потеря данных.

---

## 9. Что делать не нужно

→ Не выгружать вкладку `Тип поиска` для всех запросов, достаточно одного взгляда на неё в интерфейсе.
→ Не собирать данные через сторонние сервисы и не редактировать CSV руками: мне нужны исходные числа.
→ Не переименовывать колонки в CSV. Русские заголовки читаются нормально.
→ Не выгружать `Карты`, `Новости`, `Товары`: сайт там не участвует.

---

## 10. Что произойдёт после получения

Порядок работы по брифу, без пропусков:

❶ Свожу все запросы в одну таблицу и группирую по интентам: что такое карточка, анатомия, когда применять, раскладки, состояния, доступность, мобильные, антипаттерны.
❷ Считаю объём: число интентов × минимальное покрытие в словах, плюс разделы, которых нет у конкурентов, плюс 10 процентов на вход и закрытие. Показываю арифметику построчно.
❸ Проверяю каннибализацию по `02-pages-card.csv` и по каждой соседней странице. Если существующая страница уже в топ-10 по запросу с основой card, предлагаю расширение, а не новый текст.
❹ Сдаю на подтверждение: расчёт объёма, карту интентов, структуру H2/H3 с одним предложением на раздел, три description по 130–160 символов, план из 21 картинки с промптами, список внутренних ссылок с привязкой к абзацу, решения по каннибализации.
❺ Только после подтверждения пишу текст. Ни одного абзаца статьи до этого шага.

`readingTimeText` посчитаю по фактическому объёму в конце, а не в плане.
