Задача: закрыть четыре слота `{/* IMAGE: ... */}` в [`content/blog/agent-ui-vocabulary-design-system.mdx`](../content/blog/agent-ui-vocabulary-design-system.mdx) скриншотами с boardui.com и из документации.

Общий вывод: **три слота из четырёх закрываются скриншотами. Первый слот скриншотом с сайта не закрывается вообще** и требует либо своего прогона в агенте, либо переписывания абзаца под другую картинку.

## 0. Технические правила съёмки (для всех слотов)

| Параметр | Значение | Почему |
|---|---|---|
| Ширина окна | 1440 px, масштаб 100% | базовая ширина макета проекта |
| Плотность | 2x (Retina) | иначе текст на скриншоте мыльный |
| Тема | светлая | статья в светлой теме, тёмные скриншоты выбиваются |
| Браузер | без хрома, только страница, без курсора | `MDXImage` рисует скругление и рамку сам |
| Шрифт | дождаться загрузки (1-2 сек), иначе снимок пустым текстом | на сайтах React шрифт приходит после первого кадра |

| Папка | [`public/blog/assets/agent-ui-vocabulary-design-system/`](../public/blog/assets/agent-ui-vocabulary-design-system/) | конвенция проекта: папка = slug статьи |
| Имена | `img-1.webp` … `img-4.webp` | конвенция проекта |
| Замена | новое имя файла, не перезапись | иначе кеш Next и CDN отдают старый байт по тому же URL |

## Слот 1 — «the invented-controls baseline»

**Что написано в статье:** экран, который сгенерировал агент: центрированная белая карточка, серые поля с разным отступом, самодельный дропдаун на `div`, синяя кнопка. Красные выноски на 16 px против 20 px и на самодельный select.

**Проблема:** на boardui.com плохого интерфейса нет. Сайт показывает только свой каталог. Снять этот кадр с сайта нельзя.

### Три варианта, по убыванию честности

**Вариант А (рекомендую). Свой прогон агента.**
1. Открыть Cursor или Claude Code в пустой папке без дизайн-системы.
2. Дать ровно тот промпт, что стоит в статье:
   ```
   Build a notification settings page. Tabs for Email and Push,
   a switch per notification type, a select for digest frequency,
   and a save button.
   ```
3. Снять результат как есть, без правок.
4. Справа поставить скриншот того же экрана на BoardUI.

Это доказывает тезис статьи вместо того, чтобы его декларировать. Минус: нужен один прогон, 10-15 минут.

**Вариант Б. Только «до» + «после», без выносок.**
Левый кадр — вариант А. Правый — `/components/settings` или шаблон Settings с boardui.com. Никаких красных стрелок: сравнение двух панелей само объясняет 16 против 20 px. Это дешевле по работе и выглядит чище.

**Вариант В. Переписать абзац под доступный скриншот.**
Если прогон делать не хочется, слот убирается, а абзац про три последствия остаётся без картинки. Тогда `{/* IMAGE */}` не ставим и не притворяемся, что кадр был. Скажите — я перепишу.

**Что нужно снять в любом из вариантов:**
→ Панель настроек уведомлений, светлый фон, ширина карточки примерно 640 px, по центру кадра, вокруг серый фон страницы.
→ Состояние дропдауна: закрыт (иначе кадр читается хуже).
→ Кроп: 16:9, карточка занимает 60-70% высоты, вокруг воздух.

## Слот 2 — «the MCP prompt and result»

**Что написано в статье:** слева промпт в панели чата Cursor с видимыми вызовами `list_components` и `get_usage_examples`, справа — готовая панель настроек из Tabs, Switch, Select, Button и Toast.

**Откуда снимать:**

| Часть кадра | Источник | Состояние |
|---|---|---|
| Левая, промпт и инструменты | **свой экран Cursor**, не сайт | сессия с подключённым BoardUI, промпт из статьи в поле ввода, выше — строки вызовов инструментов |
| Правая, результат | `boardui.com/components/settings` или шаблон Settings | светлая тема, тот же порядок блоков, что в промпте |
| Если своего Cursor нет | `boardui.com/mcp`, блок «Try asking your agent» | список готовых промптов, включая про data table и про токены. Годится как «как это выглядит в документации», но не выдаёт себя за реальный вызов |

Честная оговорка: страница `/mcp` показывает **список стартовых промптов**, а не скриншот вызова инструментов. Если хочется показать именно `list_components` в работе, это только свой прогон.

**Композиция:** две панели 50/50, у обеих одинаковая высота, между ними 24 px, без рамок браузера. Или одна панель сверху (промпт), вторая снизу (результат) — если по ширине текст промпта не читается.

## Слот 3 — «the agentic component set»

**Что написано в статье:** сетка карточек: композер с тремя файлами, веб-поиск с чипами источников, индикатор «думает», стримящийся лог задач, сворачиваемый прогресс, полоса контекстного окна, двухрядный композер, один вопрос план-режима, карточка агента, орбитальный лоадер.

**Откуда снимать:** каталог и страницы компонентов. Проверил, все эти URL отдают 200:

| Компонент | URL |
|---|---|
| Composer Attachments | `boardui.com/components/composer-attachments` |
| Web Search | `boardui.com/components/web-search` |
| Agent Thinking | `boardui.com/components/agent-thinking` |
| Task List | `boardui.com/components/task-list` |
| Agent Progress | `boardui.com/components/agent-progress` |
| Composer Panel | `boardui.com/components/composer-panel` |
| Questionnaire | `boardui.com/components/questionnaire` |
| Agent Creator | `boardui.com/components/agent-creator` |
| Composer Loader | `boardui.com/components/composer-loader` |
| AI Image Generation | `boardui.com/components/ai-image-generation` |

**Ловушка:** `boardui.com/components/agent-limits` отдаёт **404**, хотя блок в каталоге есть и на `/mcp` помечен как Pro. Полосу контекстного окна придётся брать:
→ либо из общей сетки на `boardui.com/components` (там карточка Agent Limits с превью видна),
→ либо из шаблона AI Chat / Multi-agent Chat, где этот блок применяется,
→ либо из Figma, если есть доступ.

**Как собирать:** два пути.
1. **Проще и точнее:** снять секцию каталога на `boardui.com/components`, где карточки идут сеткой с подписями. Один кадр, ничего клеить не надо. Минус: карточки мелкие, надписи надо проверять на читаемость после сжатия.
2. **Аккуратнее:** снять 6-8 отдельных страниц компонентов и собрать сетку 2×3 или 2×4 в Figma. Тогда видно сами интерфейсы, а не превью-миниатюры.

Рекомендую вариант 1, а если надписи не читаются — вариант 2 на шесть компонентов: Composer Attachments, Web Search, Task List, Agent Limits (из каталога), Questionnaire, Composer Loader.

**Кроп:** 16:9, светлый фон, без выносок и подписей поверх.

## Слот 4 — «the token scale»

**Что написано в статье:** полоса шагов отступов, лестница радиусов, семантические цветовые свотчи с именами токенов, а под ними макет дашборда, который использует только эти токены, но закапывает главную метрику.

**Реальность:** отдельную публичную страницу со шкалой токенов подтвердить не удалось. `boardui.com/tokens` и `/theme` я не нашёл. Что есть точно:
→ `boardui.com/docs` — страница документации (отдаёт 200, в тексте «Tech stack React 19», «Design tokens based on Tailwind CSS», «Dark mode variables»);
→ инструмент `get_theme` в MCP — отдаёт токены темы, шкалу типографики и глобальный стиль. Но это ответ в чате, а не страница;
→ Figma-файл, если у вас есть доступ: там токены и нарисованы.

### Что делать
1. **Сначала проверить `/docs`** на раздел про токены и тему. Если раздел есть — снимаем его, это лучший вариант.
2. **Если раздела нет:** снять ответ `get_theme` в Cursor (список токенов в чате) и рядом поставить фрагмент интерфейса BoardUI. Это честно и совпадает с тем, что статья говорит про `get_theme`.
3. **Если и это не выходит:** вторая половина слота (дашборд с закопанной метрикой) скриншотом не решается в принципе — на сайте нет «плохого» дашборда. Тогда слот редуцируется до шкалы токенов, а мысль про слабую иерархию остаётся текстом.

**Кроп:** 4:3 (в статье так и стоит).
