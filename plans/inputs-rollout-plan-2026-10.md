## 2. Найденные риски (что может развалиться)

**R1. Специфичность и порядок загрузки CSS.** Webflow `.w-input[disabled]:not(.w-input-disabled)` (0,3,0) перебивает `.text-input:disabled` и красит поле в `#eee`. Override `.text-input.is-nav-search` в `globals.css` (0,2,0) спорит с новыми размерами. Порядок между `<link>` из `_document` и `globals.css` из `_app` не гарантирован, поэтому прототип и держится на `.f.f`. Лечение: у мигрированных полей **убрать класс `w-input`/`w-select`** (Webflow-база больше не утекает вообще), новые правила писать в shared CSS после старых.

**R2. Навбар.** `.nav-button-wr` это flex без `align-items`, то есть `stretch`: высоту ряда задаёт самый высокий элемент. У `button-small outlined` рамка 2px от класса `.outlined`, высота кнопки может оказаться 40 + 4 = 44, а не 40. Это надо **измерить в браузере** до выкатки, иначе M-поле 40 встанет рядом с кнопкой 44. Плюс overlay-плейсхолдер (`left: 3.143em`, `font-size: 14em`) после смены размера поля поедет относительно текста: его отступ и шрифт надо брать из тех же переменных, что у поля.

**R3. Поле с лучом в ряду с кнопкой.** Луч берёт ширину через `100cqw`, а контейнер должен быть родителем, где поле единственный ребёнок. Если повесить `container-type` на `.form-cta`, луч посчитает ширину всей формы вместе с кнопкой и уедет. Нужна обёртка `.input-wr` вокруг поля.

**R4. Фокусная кромка и подъём.** В фокусе поле поднимается на 2 и отбрасывает кромку 6 (L). Предки с `overflow: hidden` её обрежут, соседний ряд ближе 8px её перекроет. Проверить: модалка, `.blogpost_content-cta-wr`, sticky-обёртка поиска на /search, футер.

**R5. Тач-планшеты 480–991px.** Высота поля L = 50 × `--em-px`, на 768px это около 27px, а у M около 21px. Шрифт на тач-экранах поднимается до 16px, но высота нет, и тап-зона сильно меньше 44px. У кнопок та же проблема, так что пара остаётся ровной, но это решение нужно принять осознанно (варианты в разделе 4).

**R6. Двойной `height: 100%` и `display: flex` у старого `.text-input`.** В прототипе перебито фиксированной высотой. При выкатке без модификатора размера поле опять растянется по родителю. Поэтому новые правила работают только вместе с модификатором размера.

**R7. Safari и `type="search"`.** Нативная отрисовка поиска (своя скруглённая рамка, крестик) может пробиться. Нужен `-webkit-appearance: none` и скрытие `::-webkit-search-decoration`, крестик убирать там, где есть своя кнопка очистки.

## 3. Варианты внедрения

**A. Big bang.** Переписать `.text-input` целиком в shared CSS, все поля меняются разом. Быстро, но любая из проблем R1–R7 вылезает сразу на всём сайте. Не рекомендую.

**B. Новое имя класса (`.input`).** Новый компонент рядом со старым, миграция по одному месту, потом удаление `.text-input`. Максимально безопасно, но плодит второе имя и ломает договорённость «поле = `text-input`» из аудита.

**C. Opt-in через модификатор размера (рекомендую).** `.text-input` без модификатора остаётся старым и ничего не меняет. Новый вид включается только классом размера: `.text-input.is-l / .is-m / .is-s` (+ `.is-select`, `.is-attention`, `textarea-input.is-l…`). Каждое место мигрируется отдельным коммитом и проверяется. Когда все 10 мест переедут, старые правила удаляются, и `.text-input` сам по себе становится L. Это тот же путь, что прошли кнопки.

## 4. Принятые решения (по умолчанию, можно поменять одной фразой)

1. Выкатка: вариант C, по одному месту за коммит.
2. Тач-планшеты: отложить. Поле и кнопка уменьшаются одинаково, соосность не страдает. Тап-зону решаем потом одним правилом сразу для полей и кнопок.
3. Сайдбар поста: L, как сейчас (под полем стоит кнопка L).
4. Луч только в `CtaSubscribe`. В футере обычное поле, чтобы на одной странице не было двух лучей.
5. inlineCTA = `CtaSubscribe` внизу поста. `BlogInlineCta` не трогаем, новых функций не добавляем.

## 5. Как гарантировать соосность

Правила, которые закладываются в CSS и в AGENTS.md:

- **Размер поля = размер кнопки в том же ряду.** `button` ↔ `is-l`, `button-small` ↔ `is-m`, `button-x-small` ↔ `is-s`. Это единственная гарантия ровного низа.
- Любой горизонтальный ряд «поле + кнопка» и «поле + поле» выравнивается **по центральной оси**: `align-items: center`. Выравнивание по верхней грани (`flex-start`) и растягивание (`stretch`, это значение flex по умолчанию) запрещены. Кромка кнопки и фокусная кромка поля сделаны тенью и в выравнивании не участвуют.
- Если над полем есть подпись, в ряд ставится само поле, а не обёртка с подписью. В формах-сетках для этого есть subgrid: строка поля общая для всех колонок, контрол стоит в ней по центру (`align-self: center`).
- Текст внутри поля стоит на той же линии, что подпись кнопки. Подпись кнопки поднята над геометрическим центром на 1 / 0.5 / 0.5 px (отступы 9/11, 6/7, 3/4), поэтому у поля такой же сдвиг: нижний отступ `--input-l-pb` / `-m-pb` / `-s-pb` (2 / 1 / 1).
- `.nav-button-wr` (навбар) получил `align-items: center`, у `.form-cta` он уже был.
- Подсказки и ошибки под полем не должны сдвигать соседей: в формах-сетках строки задаются через `grid-template-rows: subgrid` (подпись / поле / подсказка), чтобы поля стояли на одной линии, даже если у одного есть ошибка, а у другого нет.
- Геометрия размера вынесена в переменные на самом поле: `--input-h`, `--input-r`, `--input-px`, `--input-fs`, `--input-edge-size`, `--input-lift`. Overlay-плейсхолдер навбара, иконка поиска, кнопка очистки и шеврон селекта берут отступы из них, а не из своих чисел.
- Минимальный вертикальный зазор между рядами полей ≥ кромка + подъём (L 8, M 6, S 4), иначе фокусная кромка залезет на следующий ряд.

## 6. Плотное окно настроек дашборда (переносимость)

Чтобы кто угодно мог собрать в этом стиле форму настроек:

- Токены `--input-*` переезжают в `:root` shared CSS рядом с `--btn-*`.
- Классы-помощники: `.field` (вертикальная пачка), `.field-label`, `.field-hint`, `.field-error`, `.form-row` (горизонтальный ряд), `.form-grid` (сетка на subgrid).
- Правило плотности: маркетинг и подписка = L, интерфейс приложения и навбар = M, плотные панели настроек, таблицы и фильтры = S. Внутри одной панели один размер.
- Эталон: на прототипе появляется секция «Settings panel» на S и M (два столбца полей, селекты, textarea, ряд кнопок Save / Cancel, ошибки и подсказки разной длины). Она служит приёмочным тестом соосности до выкатки.

## 7. Проверка перед каждым коммитом миграции

- Ширины 1440 / 1024 / 768 / 390, Chrome и Safari.
- Состояния: покой, hover, focus (кромка не обрезана), ошибка, disabled во время отправки.
- Линейка в DevTools: низ поля = низ кнопки в покое, ±0.5px.
- `npm run lint`.
