<span class="blog_big-paragraph">[agent-desktop](https://agent-browser.dev/desktop) is a command-line tool from [Vercel Labs](https://github.com/vercel-labs/agent-desktop) that reads a desktop app's accessibility tree and prints it as JSON. Every element your agent can act on gets a ref, a short id such as `@s26u7pv9qta5g4:e6`. The agent clicks the ref instead of guessing at pixels, then reads the tree again.</span>

agent-desktop is a tool your agent calls, and the observe, act, verify loop lives in the coding agent. There is no model inside it, and nothing below is a transcript: every agent-desktop command and every value the docs quote comes from the published pages.

It started as an independent project under the GitHub handle lahfir, appeared on [npm](https://www.npmjs.com/package/agent-desktop) in February 2026, and reached Vercel Labs with 1.0.2 in late October.

It sees only apps that publish an accessibility tree: native controls on all three systems do, canvas surfaces do not.

_Every agent-desktop command below is quoted from the 1.0.2 documentation, November 2026; the jq and shell around them are written for this article. Nothing was run on the author's machine, and every visual is drawn from the documented shapes, not captured from a screen. The docs track the current release, not the version pinned here, and the CLI ships weekly: check every flag against the live page before you use it._

After the [open source digest](/blog/open-source-tools-digest-2026-10), this is the first long review in our Tools category: nine jobs, one per check a desktop team runs before a release. Three others fail, and they decide if you install it.

## What it is, in four commands

The docs show the whole idea on GNOME Calculator: map the window, drill into a region, press 7, wait for the display to read 7.

```bash
agent-desktop snapshot --app gnome-calculator --skeleton -i --compact         # 1. map: a shallow skeleton
agent-desktop snapshot --root @s2txcl95uvubmn:e1 -i --compact                 # 2. drill: expand one region
agent-desktop click @s2txcl95uvubmn:e11                                       # 3. act: press the 7 button
agent-desktop wait --element @s2txcl95uvubmn:e6 --predicate value --value 7   # 4. verify: the display reads 7
```

<p class="blog-source">Docs: <a href="https://agent-browser.dev/desktop/quick-start" target="_blank" rel="noopener noreferrer">Quick start</a></p>

## Before you hand it anything

{/* SLOT 03 | permissions | 1:1 | float right | illustration | /blog/assets/agent-desktop-use-cases/03-permissions-granted.webp | prompt: one app window outline with three permission tabs beside it, two filled and ticked, the third empty, a surface list drawn as five small labelled chips underneath, thin drafting line work on cream | alt: an empty app window beside two ticked permissions, Accessibility and Screen Recording, an unticked Automation below them, and five surface chips reading window, menu, sheet, alert, popover */}

<div class="blog-img-float blog-img-float--right">

![An empty app window beside two ticked permissions, Accessibility and Screen Recording, an unticked Automation below them, and five surface chips reading window, menu, sheet, alert, popover](/blog/assets/agent-desktop-use-cases/03-permissions-granted.webp)

<p class="blog-figcaption">Two states, one list.</p>

</div>

Install is one line on Node 18 or later. Then run `agent-desktop status` and read two fields: `permissions.accessibility.state` should say `granted`, and `supported_surfaces` should not be empty.

→ **macOS.** macOS 13 or later. The Accessibility grant belongs to whichever app launched the CLI, so Terminal and VS Code each need their own. `permissions --guide` opens the right pane.

→ **Windows.** Windows 10 1809 or later, inside the signed-in desktop session. Session 0, Server Core, the secure desktop and a locked desktop are not supported, and an app running as administrator can be read but not driven from a lower-integrity terminal.

→ **Linux.** Ubuntu 24.04 or later with a running AT-SPI bus. An empty `supported_surfaces` means the bus did not answer.

Headless is the default: ref actions go through the accessibility API without moving the pointer or taking focus. `--headed` is permission for physical input.

Refs belong to their snapshot. After the UI changes, an old ref fails with `STALE_REF` or matches an element you no longer meant.

Three edges the docs attach, each changing the prompt rather than the command:

→ **Windows, physical input.** `type`, `focus` and `right-click` are headed-only there and return `POLICY_DENIED` headless. `set-value` writes the field without keystrokes.

→ **Quit shortcuts on macOS.** The docs put `cmd+q` at `POLICY_DENIED` unless you pass `--force`, and name `close-app` as the way to quit an app.

→ **Redaction has an edge.** Trace lines swap sensitive fields, such as text, value, name and description, for `{ "redacted": true }`. Session screenshots, the exported HTML and visual debug files are not redacted.

<p class="blog-source">Docs: <a href="https://agent-browser.dev/desktop/guides/traces" target="_blank" rel="noopener noreferrer">Traces</a> · <a href="https://agent-browser.dev/desktop/platforms/windows" target="_blank" rel="noopener noreferrer">Windows</a></p>

The jobs are one review process: the unnamed-control list from job 1 is what makes the `find --exact` calls in job 8 trustworthy. Jobs 1 to 3 make artifacts, 4 to 6 gate a release, 7 to 9 leave evidence for whoever defends a fix. Pick by who reads the result.

The prompts name an app called `Acme`. Substitute the name `list-apps` prints for your build.

## For designers

Designer jobs share one property: the result is an artifact a human reads, so a wrong click costs a re-run.

### 1. Audit a screen's accessibility in one pass

**The job.** List every control on one screen that a screen reader would announce badly.

**Prompt.**

```text
Run agent-desktop skills get desktop and follow it. Scope the read to the
Settings window with --window-id from list-windows, and snapshot it with -i and
without --compact. Click nothing. List every node with a ref_id but no name, and
every node whose role does not match what it does. Output a table: ref, role,
current name, problem, suggested fix.
```

**Commands.**

```bash
agent-desktop skills get desktop                                                     # load the loop rules
agent-desktop list-windows --app "Acme"                                              # window ids for this app
agent-desktop snapshot --window-id "<ID>" -i > settings.json                         # Settings only, not the whole app
jq '.. | objects | select(.ref_id and (.name == null)) | select(.children == null and .children_count == null)' settings.json
agent-desktop get "<REF>" --property role                                            # read the role back
```

<p class="blog-source">Docs: <a href="https://agent-browser.dev/desktop/snapshots-and-refs" target="_blank" rel="noopener noreferrer">Snapshots and refs</a> · <a href="https://agent-browser.dev/desktop/skeleton-and-drill-down" target="_blank" rel="noopener noreferrer">Skeleton and drill-down</a></p>

**What it proves.** A node carries `name` only when it has one, and empty fields are omitted, so a ref with no `name` key is a control with no accessible name. That is the failure [WCAG 4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value) describes, found without an inspector.

**Where it breaks.** The list covers only what the read reached. A snapshot that runs out of budget still succeeds, with `data.complete` set to `false`, since `--timeout-ms` defaults to 3000. Drill each region with `--root` first.

### 2. Capture every state of a component for review

**The job.** Put five states of one component into a folder whose names sort the same on every run: default, hover, focus, disabled, error.

**Prompt.**

```text
In "Acme", open Profile. Screenshot the window with the "Save" button in five
states into ./review/profile-save/ as 01-default.png to 05-error.png. Disabled
appears when Email is empty; error appears after saving "roman@". Use --headed
only for hover. Re-find the button before each step; stop if a state is missing.
```

**Commands.**

```bash
agent-desktop find --app "Acme" --role button --name "Save" --exact --first   # button ref
agent-desktop screenshot ./review/profile-save/01-default.png --app "Acme"     # baseline
agent-desktop --headed hover "<REF>"                                           # physical hover
agent-desktop focus "<REF>"                                                    # semantic, headless on macOS
agent-desktop is "<REF>" --property enabled                                    # confirm disabled
```

<p class="blog-source">Docs: <a href="https://agent-browser.dev/desktop/commands/interaction" target="_blank" rel="noopener noreferrer">Interaction</a> · <a href="https://agent-browser.dev/desktop/commands/mouse" target="_blank" rel="noopener noreferrer">Mouse</a></p>

**What it proves.** The five states stop depending on someone clicking through a build. I take the reference for each state from the [AI inspiration gallery](https://app.setproduct.com) and name files the way [Material Desktop](/templates/material-desktop) names frames.

**Where it breaks.** The agent cannot invent a state. Disabled and error exist only if you name the input that triggers them. A headed hover moves your real cursor.

### 3. Diff a flow before and after a redesign

**The job.** Run one flow on the old build and the new one at the same window size, then pair the screenshots.

**Prompt.**

```text
Resize "Acme" to 1280x800. Run checkout: Cart, Shipping, Payment, Review.
Screenshot each screen to ./diff/old/ as 01-cart.png to 04-review.png, then
stop so I can install the new build. Repeat into ./diff/new/ with the same
names and write ./diff/index.md pairing old and new side by side.
```

**Commands.**

```bash
agent-desktop resize-window --app "Acme" --width 1280 --height 800                # freeze the viewport
agent-desktop find --app "Acme" --role button --name "Continue" --exact --first   # ref for this build
agent-desktop click "<REF>"                                                       # one step
agent-desktop wait --text "Shipping" --app "Acme" --timeout 5000                  # next screen up
agent-desktop screenshot ./diff/old/02-shipping.png --app "Acme"                  # stable name
```

<p class="blog-source">Docs: <a href="https://agent-browser.dev/desktop/commands/app-window" target="_blank" rel="noopener noreferrer">App and window</a></p>

{/* SLOT 06 | before and after | 16:9 | full width | illustration | /blog/assets/agent-desktop-use-cases/06-before-after-pair.webp | prompt: the same window outline twice side by side at one ruler width, the left one plain and the right one with three outlined regions marked as changed, a single measurement line across the top, thin drafting line work on cream | alt: two copies of one sign-up form at 1280 px, the right one boxing the header bar, the email field and the submit button as changed */}

![Two copies of one sign-up form at 1280 px, the right one boxing the header bar, the email field and the submit button as changed](/blog/assets/agent-desktop-use-cases/06-before-after-pair.webp)

<p class="blog-figcaption">Every difference is the redesign.</p>

**What it proves.** Both builds are compared on identical frames, so the difference belongs to the redesign.

**Where it breaks.** Refs from the old build mean nothing on the new one. If the redesign renamed Continue to Next, the second run dies on step one, so give the agent both labels.

## For release owners

These jobs gate a release. They pay off when a missed bug costs more than a prompt.

### 4. Smoke the onboarding before a release

**The job.** Walk first-run onboarding on a clean install and halt on the first screen that fails to appear.

**Prompt.**

```text
Launch "Acme" on a clean profile. Screens: Welcome, Create workspace, Invite
team, Done. On each, find the primary button, then run one batch with
--stop-on-error: wait until it is enabled, click it, wait 10 seconds for the
next heading. Halt on the first miss; report screen, snapshot id, error code.
```

**Commands.**

```bash
agent-desktop launch "Acme"                                                         # start the app
agent-desktop wait --window "Acme" --app "Acme" --timeout 15000                     # window exists
agent-desktop find --app "Acme" --role button --name "Get started" --exact --first  # screen ref
agent-desktop batch '[
  {"command": "wait",  "args": {"element": "@<snapshot_id>:eN", "predicate": "enabled", "timeout": 5000}},
  {"command": "click", "args": {"ref_id": "@<snapshot_id>:eN"}},
  {"command": "wait",  "args": {"text": "Create workspace", "app": "Acme", "timeout": 10000}}
]' --stop-on-error
```

**What it proves.** `--stop-on-error` turns the first missing screen into a halt with a `stopped.reason`, not a skip to the next entry. If onboarding is a long tooltip tour, [contextual help](/blog/how-to-replace-onboarding-with-contextual-help) shortens the walk.

<p class="blog-source">Docs: <a href="https://agent-browser.dev/desktop/guides/batch" target="_blank" rel="noopener noreferrer">Batch</a></p>

**Where it breaks.** A batch can use a ref you already found before it starts, and it cannot create one: nothing in the array reads the tree. So one batch covers one screen, and the next screen is checked by text. The docs record a batch returning `ok: true` with `stopped: { "index": 1, "reason": "stop_on_error" }`, so the exit code stays 0.

### 5. Push a signup form through its empty and invalid states

{/* SLOT 08 | invalid form | 1:1 | float right | illustration | /blog/assets/agent-desktop-use-cases/08-invalid-email-error.webp | prompt: one form outline with two fields, the second holding a malformed address and underlined in error, a short caption line beneath it drawn as a marked text block, thin drafting line work on cream | alt: a Sign up window holding Acme in Name and roman@ in Email, the field underlined in red under the message Enter a valid email, Create account greyed out */}

<div class="blog-img-float blog-img-float--right">

![A Sign up window holding Acme in Name and roman@ in Email, the field underlined in red under the message Enter a valid email, Create account greyed out](/blog/assets/agent-desktop-use-cases/08-invalid-email-error.webp)

<p class="blog-figcaption">Copy is compared, not matched loosely.</p>

</div>

**The job.** Submit the signup form empty, then with a malformed email, and check the error copy word for word.

**Prompt.**

```text
In "Acme", open Sign up. Submit it empty and confirm [your empty-field copy].
Type "roman@" into Email, submit, then confirm [your invalid-email copy].
Read each error back with get --property text and report any difference
from the expected copy, character for character.
```

**Commands.**

```bash
agent-desktop find --app "Acme" --role textfield --name "Email" --exact --first          # field ref
agent-desktop type "<REF>" "roman@"                                                      # ref action, headless
agent-desktop click "<REF>"                                                              # submit
agent-desktop wait --text "[your invalid-email copy]" --app "Acme" --timeout 5000        # the copy you expect
agent-desktop get "<REF>" --property text                                                # read it back
```

<p class="blog-source">Docs: <a href="https://agent-browser.dev/desktop/commands/observation" target="_blank" rel="noopener noreferrer">Observation</a> · <a href="https://agent-browser.dev/desktop/commands/wait" target="_blank" rel="noopener noreferrer">Wait</a></p>

**What it proves.** The check is literal: a designer signs off on one sentence, and a build that ships a shorter one fails here first. The [input UI design guide](/blog/input-ui-design) covers that sentence.

**Where it breaks.** `wait --text` matches a case-insensitive substring, so it passes when the words sit inside a longer, wrong sentence, and the `get` read-back catches that.

### 6. Run a release gate that fails loudly

{/* SLOT 09 | release gate | 2:3 | float right | illustration | /blog/assets/agent-desktop-use-cases/09-release-gate.webp | prompt: a tall narrow gate drawn as a drafting elevation, three checks stacked as barred panels, a version stamp at the top, an exit code 1 arrow at the bottom, thin drafting line work on cream | alt: a gate stamped 1.0.2 with three stacked panels for status, version and screen, each one ticked, and a red arrow leaving the bottom labelled 1 */}

<div class="blog-img-float blog-img-float--right">

![A gate stamped 1.0.2 with three stacked panels for status, version and screen, each one ticked, and a red arrow leaving the bottom labelled 1](/blog/assets/agent-desktop-use-cases/09-release-gate.webp)

<p class="blog-figcaption">Three checks, one exit code.</p>

</div>

**The job.** Before tagging a release, check the machine, log the CLI version and confirm the first screen renders, in one script that exits non-zero on any miss.

**Prompt.**

```text
Write gate.sh. Exit 1 unless agent-desktop status shows accessibility granted.
Log agent-desktop version. Run gate.json through agent-desktop batch with
--stop-on-error and exit 1 if any entry has ok: false. gate.json uses only
entries that need no refs: launch, wait with window, wait with text.
```

**Commands.**

```bash
agent-desktop status | jq -e '.data.permissions.accessibility.state == "granted"'   # exit 1 if not
agent-desktop version | jq -r '.data.version'                                        # log release
agent-desktop batch "$(cat gate.json)" --stop-on-error > gate-result.json            # saved checks
jq -e '[.data.results[].ok] | all' gate-result.json                                  # real verdict
```

<p class="blog-source">Docs: <a href="https://agent-browser.dev/desktop/commands/system" target="_blank" rel="noopener noreferrer">System</a> · <a href="https://agent-browser.dev/desktop/commands/batch" target="_blank" rel="noopener noreferrer">Batch</a></p>

**What it proves.** The gate fails in the language CI understands, exit code 1. Logging `version` ties a pass to a release, which matters for a tool that shipped 1.0.0 and 1.0.2 in a week.

**Where it breaks.** A saved file cannot hold refs, because refs die with their snapshot, so the gate checks screens and leaves clicks to jobs 4 and 8. There is no replay command, and `trace show` only reads a session back. Batch failures land at exit 0 too, which is why the last line reads `ok` and not `$?`.

## For developers

Developer jobs turn a vague report into evidence an engineer opens.

### 7. Replay a bug report exactly as written

**The job.** Follow a user's steps to reproduce verbatim and capture the window and the tree at the step that fails.

**Prompt.**

```text
Reporter's steps for "Acme" 2.4.1, unchanged: [paste steps]. Start a session
named bug-412. Run the steps in order and wait for each result the reporter
describes. At the first miss, save a screenshot and the full tree to
./bug-412/, then stop. Add no steps the report lacks. Then write
./bug-412/check.sh with the failing step as one assertion, so job 9 can rerun
it.
```

**Commands.**

```bash
export AGENT_DESKTOP_SESSION="$(agent-desktop session start --name bug-412 | jq -er '.data.session_id')"
agent-desktop wait --text "Export finished" --app "Acme" --timeout 10000            # step 3 result
agent-desktop screenshot ./bug-412/step-3.png --app "Acme"                          # failing frame
agent-desktop snapshot --app "Acme" > ./bug-412/step-3-tree.json                    # the tree
agent-desktop --debug --screenshot ./bug-412/step-3.html snapshot --app "Acme" -i   # labelled bounds
```

<p class="blog-source">Docs: <a href="https://agent-browser.dev/desktop/sessions" target="_blank" rel="noopener noreferrer">Sessions</a> · <a href="https://agent-browser.dev/desktop/guides/traces" target="_blank" rel="noopener noreferrer">Traces</a></p>

{/* SLOT 10 | bug replay | 16:9 | full width | illustration | /blog/assets/agent-desktop-use-cases/10-bug-replay-evidence.webp | prompt: one window outline split in two panels, the left panel drawing a frame with one region boxed, the right panel drawing a tree of labelled nodes, a single vertical line tying the boxed region to its node, thin drafting line work on cream | alt: an Export window with the progress bar boxed beside an accessibility tree running from window e1 down to text e7, the two tied by one red line */}

![An Export window with the progress bar boxed beside an accessibility tree running from window e1 down to text e7, the two tied by one red line](/blog/assets/agent-desktop-use-cases/10-bug-replay-evidence.webp)

<p class="blog-figcaption">One frame beside one tree.</p>

**What it proves.** The engineer gets the failing frame next to its tree, tied to one step and one session, so a "cannot reproduce" reply becomes a comparison.

**Where it breaks.** Reports skip steps. A reporter writes "open the file" and leaves out the dialog; tell the agent to stop there, because a guessed step reproduces a different bug. The debug HTML is unredacted, so strip customer data first.

### 8. Regression-pass the critical flows after a migration

**The job.** After rebuilding the app on a new UI framework, run the three flows that make money and collect every failure into one report.

**Prompt.**

```text
"Acme" was rebuilt on a new framework. Run sign in, create project, export
PDF; they end on "Projects", "Untitled project" and "Export finished".
Re-find refs per screen, one batch per screen with --stop-on-error, and move
to the next flow after a failure. Write report.md: flow, step, expected, error.
```

**Commands.**

```bash
agent-desktop find --app "Acme" --role button --name "Sign in" --exact --first       # live ref
agent-desktop batch "$(cat flow-1-step-1.json)" --stop-on-error > flow-1-step-1.out   # one screen
jq '.data.stopped // empty' flow-1-step-1.out                                         # where it halted
jq -r '.data.results[] | select(.ok == false or .ok == null) | [.index, .error.code] | @tsv' flow-1-step-1.out
```

<p class="blog-source">Docs: <a href="https://agent-browser.dev/desktop/commands/batch" target="_blank" rel="noopener noreferrer">Batch</a></p>

**What it proves.** The flows that pay for the product pass on the rebuilt app, each end state asserted by name. Without them, a migration counts as done because nothing crashed.

**Where it breaks.** Migrations change the tree more than the pixels. A button can come back with a new role or no name, and every `find --exact` misses, so run job 1 on the new build first. On Windows, menus in WinUI 3 hosts are not detected.

### 9. Prove a fix closed the bug

**The job.** Run the assertion from the bug report on the old build and the fixed one, and keep both results.

**Prompt.**

```text
Run ./bug-412/check.sh against "Acme" 2.4.1, then 2.4.2, three times each.
The check clicks Export and waits 10 seconds for "Export finished". Report
exit and error codes. The fix is proven only if 2.4.1 fails every time and
2.4.2 passes every time.
```

**Commands.**

```bash
agent-desktop find --app "Acme" --role button --name "Export" --exact --first   # ref for this build
agent-desktop click "<REF>"                                                     # the path the report walks
agent-desktop wait --text "Export finished" --app "Acme" --timeout 10000        # expect a timeout on 2.4.1
echo "exit $?"                                                                  # 1 there, 0 on 2.4.2
```

**What it proves.** A green run alone proves nothing: the red run shows the check sees the bug, the green that the fix closed it.

**Where it breaks.** A flaky check passes both ways. If the old build passes once in three, it measures timing, not the bug, so wait on a different element first.

**Anything drawn to a canvas.** Design-tool canvases and 3D viewports expose no tree for what they draw, and neither do chart libraries that paint to `<canvas>`. You get a window with a few nodes and no refs where the shapes are, which the macOS docs call custom-rendered UI. Use a vision agent there, or ship an accessible table beside your [charts](/blog/chart-ui-design-guide).

**Web content inside the app.** agent-desktop does not automate web pages. For a Chromium or Electron app you launch fresh, `launch "Acme" --cdp` opens a loopback DevTools port, [agent-browser](https://agent-browser.dev/) takes the web contents, and agent-desktop keeps the native menus. The warning signs are a thin tree and a `--cdp` refusal when the app is already open, so quit it first.

**Login walls and dialogs outside the tree.** A captcha exists to stop automation, and the agent should stop at it. UAC prompts are unsupported, and Electron's native dialogs are missing from the Linux tree. Sign in yourself first, use an account without a captcha, and pass file paths through the app's fields.

## The verdict

agent-desktop is a QA and audit tool. As a daily driver it asks for prompts about clicks you could make in seconds.

The speed argument is in its own docs: [the quick start](https://agent-browser.dev/desktop/quick-start) puts the calculator check at 286 ms and [the wait docs](https://agent-browser.dev/desktop/commands/wait) put a title wait at 112 ms, while a vision agent pays for a screenshot and a model call per step. Across a 200-step pass the gap compounds.

Worth it for desktop products with a test cadence, where jobs 4 to 6 run every release. Oversold for everything else. If you design the agent's side of the loop too, the [approval and undo patterns](/blog/ai-agent-ui-design-patterns) are the human half.

## Frequently asked questions

### Does agent-desktop need a vision model?

No. It has no model inside and never looks at pixels to find an element. It reads the accessibility tree the operating system already exposes and hands back JSON with refs. Your coding agent does the reasoning, and screenshots exist only as evidence for a human reviewer.

### Can agent-desktop automate a website?

No, and the docs say so directly. Web pages belong to agent-browser. For a Chromium or Electron app you launch fresh, --cdp opens a loopback DevTools port. agent-browser connects to it for the web contents, and agent-desktop keeps the native menus and dialogs.

### Which apps can agent-desktop not see?

Anything that publishes no accessibility tree. Canvas surfaces such as design tools and 3D viewports show up as a window with few nodes and no refs. Windows UAC prompts and locked screens are out of reach, and on Linux, Electron's native dialogs are missing from the AT-SPI tree.

### Is it safe to let agent-desktop click around my desktop?

Safer than most options. Ref actions run headless by default, without moving your cursor or taking focus. Quit shortcuts such as cmd+q come back as POLICY_DENIED unless you pass --force. The real risk is data: snapshots and screenshots contain whatever was on screen, so keep them out of public repos.

### Does agent-desktop work headless?

Headless is the default for ref actions, which go through the accessibility API. It still needs a live desktop session: the signed-in interactive desktop on Windows, a graphical session with an AT-SPI bus on Linux. The Linux page puts its test environment on Xvfb with openbox, the realistic path into CI.
